# TOKEN 魔塔

游戏只有一个入口 `/arcade/tower`，统一为一百层完整战役。旧的 `campaign` 查询参数不再切换游戏。一百层地图是本项目新增的固定关卡，不是把所引用的十层开源项目称作原版百层，也不只是重复原来的十层地图。

## 一百层关卡与规则

- 静态关卡位于 `frontend/src/games/token-tower/expedition/campaign.json`，共 100 张不同的 14×14 地图，约 62 KB（未压缩）。分为石堡、余烬、霜雪、暮影、王冠、沙海、风暴、冥河、星界、永夜十个连续区域。
- 每十层一位区域首领，第 10 / 20 / … / 100 层的首领封锁上层或王座。最后一层救援必须已击败全部十位首领；第十层不会提前通关。
- 80 组敌人数值配置（每区八类），沿用同一像素图集的精灵，能力包含普通攻击、先攻、双重反击与无视防御的魔法攻击。并非 80 套新增美术。精确战损包含本局伪随机的暴击与闪避，预览不消耗随机状态，撤销不能重掷。
- 钥匙、黄门主线、蓝门与红门支路、剑盾、属性宝石、药水、怪物图鉴和商店分布在各层。已收集宝物和已击败敌人不刷新，开门只扣一次钥匙；楼梯可以往返补给。
- 骑士初始 600 HP / 18 攻击 / 12 防御；游侠 680 HP / 17 攻击 / 12 防御，闪避更高。药水与装备增益随区域提升。每区第 3、7 层设神像；商店属性价格 / 增益随所在区域变化，钥匙价格固定。游戏内预览和实际购买使用同一报价函数。
- 通关一星；累计战损低于 100,000、击败至少 280 名敌人，各加一星。
- `prepare-campaign.py` 是开发阶段生成固定地图数据的工具，固定种子，产物提交后在浏览器直接读取；不会在服务器或浏览器运行 Python，也不会每次开局随机重做地图。修改已发布关卡时需调整存档版本并处理兼容，不应悄悄覆盖地图。

## 像素素材与基础规则来源

- 上游：[Armour/Magic-Tower-Qt](https://github.com/Armour/Magic-Tower-Qt)，固定 revision `a32ee738485fa210e3a2b32cf57f506d51446c13`。
- 原仓库许可证为 MIT，Copyright (c) 2014 Chong Guo。原文保留在 [classic/LICENSE.txt](classic/LICENSE.txt)，游戏页也提供许可链接。本移植沿用原仓库发布的素材和许可声明，并不声称这些第三方素材为本项目原创。
- 地图与 13 种怪物数值提取自 `MagicTower/database/data.sql`；地图各为 14×14，共十层，静态数据位于 `frontend/src/games/token-tower/classic/campaign.json`。原 SQL SHA256：`cb0fe7a0c95acb6d7873339e194f10b10ba8597620ef4e474b13c55d21079cc9`。
- 像素素材提取自 `MagicTower/assets`，合并为本地无损 WebP 图集 `classic/sprites.webp`（53,276 bytes）；封面用第一层地图与相同精灵合成。
- 复现资源：`python frontend/src/games/token-tower/import-classic.py /path/to/Magic-Tower-Qt`。脚本核验上游 revision 后转换 SQL、合成图集并复制许可证。Python、Pillow、SQLite 仅在开发时使用。

## 浏览器实现与资源边界

- Qt/C++ 程序没有作为后端运行。移动、寻路、战斗模拟、暴击、闪避、经验、门锁、拾取、首领封印、图鉴、商店与结算都由前端 TypeScript 执行。
- 当前游戏存档为 `token-tower-100-v1:<userId>`，浏览器 localStorage 用于快速恢复，同时同步到 TOKEN 乐园服务端；校验关卡版本、0–99 层边界、数值、坐标、移除地块及撤销历史。恢复时暂停。内存保留最近 60 步，存档保存最近 20 步撤销；切换账号先保存再加载对应账号。旧的 `token-tower-classic-v1` / `token-tower-v2` 存档不覆盖、不伪装转换为一百层进度，页面没有旧版切换入口。
- 地图和代码随游戏页懒加载，像素图集复用 53 KB 的本地静态 WebP。游戏没有专用后端、数据库表、WebSocket、轮询、每步请求、运行时生图或外链素材下载。服务器承担正常站点鉴权与静态资源传输；计算、动画和存档占用玩家浏览器的 CPU、内存与本地存储。不能将这表述为服务器绝对零流量。
- 金币与分数用于游戏，不能兑换 API 额度；客户端成绩不作为真实额度奖励凭据。
- 默认站点内嵌，不在开始 / 继续时自动进入沉浸模式。桌面左侧属性 / 钥匙 / 装备、中间方形地图、右侧战况 / 目标 / 商店；地图与两栏间距 8px，整组按宽高居中适配。手机窄容器上下排列，小竖屏详情可展开。
- WASD / 方向键、相邻格点击、空地点击寻路、触屏方向键和手柄；B 图鉴，Z 撤销，P 暂停。失焦 / 隐藏自动暂停。战斗有双方精灵、血条、斩击、受击、暴击、闪避和跳过；长战斗分组播放，最多十六个节拍（含先攻）。结果只结算一次，动画时锁定移动与撤销，暂停 / 跳过不重复发奖励；结束后可撤销。减少动态效果偏好关闭位移与闪烁。

## 验证与历史参考

- `expedition/__tests__/campaign.ts` 只通过正常移动、拾取、战斗、购买及楼梯行动通关，不改角色数值或移除地图敌人。覆盖骑士 / 游侠，种子 1 / 7 / 99 六条完整路线；每次上楼都保存并载入，包含后期两位数楼层、折返商店、十位首领与王座救援。通过这些路线不代表任意资源选择或所有随机种子必然通关。
- `classic/engine.ts` 与其十层地图作为移植兼容性回归资料保留。旧版 3,766 次合法输入回放仍验证共享引擎重构未改变原始战斗规则，不作为产品中的另一款游戏。
- 历史初版十张 11×11 地图、三符文 / 背包药剂规则及相应源码测试保留作参考，不再有独立产品入口。初版像素来自 [Kenney Tiny Dungeon](https://kenney.nl/assets/tiny-dungeon)，作者 Kenney，CC0，许可见 [License.txt](License.txt)。
- 界面 / 动画研究见 `docs/token-tower-layout-research.md`；一百层说明见 `docs/token-tower-100-floor-campaign.md`。

## 五十层旧档升级

首次没有百层存档时，先用 `legacy-50.json` 的原地图与数值验证旧 `token-tower-50-v1:<userId>`，再转换为百层档；原键保留。未通关者保留原位置与全部属性 / 道具 / 战斗进度，暂停后继续。已经完成五十层者也可从第 50 层继续，旧最终积分奖励扣除，等第 100 层救援时再结算。旧撤销历史在升级时清空，避免旧终点回滚；新游戏正常积累撤销。新存档优先，迁移不会覆盖已经开始的百层进度。完整细节见百层说明。
